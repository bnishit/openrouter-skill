Inspect the results and limits ↗
How to read the evaluation

The runner receives the task and available reference text, but not the grading gates. Skill auto-discovery, tools, network, and account writes are disabled in the run. A separate clean model context grades shuffled answers against outcome gates. The grader uses the same model family, so this is blind grading, not a cross-model or human certification. Three trials are an early signal, not a broad reliability guarantee.

Cases include representative tasks, failure cases, scope boundaries, and held-out tasks. Development failures and retests stay in the release record; an average cannot erase a failed hard gate. No-skill and previous-release results are kept alongside the candidate.

Before you use it

The useful limits.

Does it implement every OpenRouter feature?

No. The references map 30 capability areas. The supplied Next.js/Express starters implement selected chat and image routes. Worked samples cover narrower server/CLI patterns. New product surfaces still need their own implementation and checks.

Why use this with an official SDK?

The SDK gives you typed calls and client behavior. This skill helps choose the API, preserve state, handle failure, and audit cost. The Client SDK and Agent SDK have different jobs; the skill explains that boundary.

How does it stay current?

Focused checks verify selected official assumptions. The inventory check flags added or removed indexed pages and API operations. Existing page/schema changes can still need manual review. The capability map includes source links and dated migration notes.

Is it ready to expose as a public proxy?

The samples are not an authentication, quota, or tenant-isolation system. Add those controls for your app and test with your account before exposure. Keys belong on the server; account and admin changes need their own authorization.
